# Wisal branding and product launch plan

## Phase 1 — Foundation (implemented in this checkpoint)

- Unified bilingual typography, palette, logo assets, PWA icons, cinematic public hero, branded authentication, and documented usage rules.
- Neon Auth adapter isolated behind a feature flag.

## Phase 2 — Product-wide adoption

- Apply brand tokens to studio, guest experience, user dashboard, admin dashboard, emails, empty states, and support surfaces.
- Replace one-off colors and typography with reusable semantic tokens and component variants.

## Phase 3 — Invitation system

- Build template families, multiple opening experiences, multiple internal layouts, media rules, localization rules, and accessibility requirements.
- Add template preview and quality gates for Arabic, English, mobile, and large screens.

## Phase 4 — Multi-stage events and guest targeting

- Complete segment-specific visibility, guest groups, per-stage RSVP, personalized messages, and privacy tests.

## Phase 5 — Operations and launch readiness

- Production auth migration, email delivery, observability, rate limiting, backups, support workflows, performance budgets, accessibility QA, and end-to-end regression tests.

## Phase 6 — Monetization

- Activate real payments only after the preceding gates pass. Start with event-based plans, paid template upgrades, and optional premium services; keep core RSVP reliable and understandable.
